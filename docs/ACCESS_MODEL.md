# Access model

## Core rule
Every person must have an individual identity in the system. Shared permission groups may exist, but they must not replace person-level identity or authorship.

- student content must remain attributable to the individual student
- do not use one collective student identity for authorship

## Invite flow
1. Admin chooses the person's named role.
2. The system registers the invitation/pre-registration.
3. The authentication service sends the access link.
4. On account creation, the user is linked to the pre-registration.
5. The individual profile receives the correct named role.
6. Permissions are loaded for that role.
7. Future actions remain attributable to that user's unique ID.

## Validation checklist before inviting anyone
1. Named role appears in the selector.
2. Permissions for that named role are correct.
3. Pre-registration is saved successfully.
4. Access link is sent.
5. Individual profile exists after first access.
6. Correct role is assigned.
7. Visible areas match the intended scope.
8. Edit/delete/attachment actions match the intended scope.
9. Authorship shows the correct person.
10. No identity collision occurs between people with similar functions.
